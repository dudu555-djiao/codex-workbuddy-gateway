# Codex 指挥 WorkBuddy 的大白话讲解

这是设计讲解，录制时应以当前实机验收为准。v0.2.0 的桌面 ACP 方式实测失败；v0.3.0 改为任务队列，已在 2026-10-08 验证简单清单与同一会话返工。不能把这项小测试说成已经验证所有复杂任务。

Codex 像安排工作和验收的负责人，WorkBuddy 像负责实际执行的同事。两边中间有一个本机程序，叫 Gateway。它像一个共享任务箱，保存该做什么、做到了哪一步，以及交回了什么。

第一次，我们在桌面 WorkBuddy 里启动一个专用对话，让它定期从任务箱里拿任务。以后 Codex 下达任务时，把指令写进这个任务箱；WorkBuddy 自己领走，用自己的工具做完，再把结果和真实文件路径放回来。

Codex 不只是转发。它要打开实际文件、检查内容和测试。没做好，就把具体问题作为下一轮任务放回任务箱。WorkBuddy 在同一个对话里继续领取和修改。检查通过才记录验收。

所以这次的连接方式是“Codex 用 MCP 操作任务箱，WorkBuddy 用本地命令领取和回报”。不依赖尚未验证的桌面 HTTP ACP 接口，也不用独立 CLI 模型冒充桌面 WorkBuddy。首次启动可能需要点界面发一条指令；后续任务和返工通过队列自动传递。

Health 就是看 WorkBuddy 现在有没有在等任务。它不检查任务做得好不好。还需要注意，WorkBuddy 停止监听以后不会自动醒来，需要重新启动那个执行对话；回报也不等于验收，Codex 仍然需要独立检查成果。
